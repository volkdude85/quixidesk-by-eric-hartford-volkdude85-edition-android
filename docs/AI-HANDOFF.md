# Notes for whoever picks this up next

Written for an AI or an engineer arriving cold, with no memory of the work. It is deliberately blunt
about what is finished, what is a stub, and what will bite you.

## What this project is

An Android application that runs a full assistant — model interface, memory, tools, mail — inside the
APK, with no computer required. It syncs its state with a desktop over the local network, Palm-style:
you arrive, it notices, it catches up.

Two things are true at once and it is worth holding both:

1. **It is a general product.** Nothing in this repository belongs to one person. Personas are build
   inputs, memory is a file, and the sync is a protocol.
2. **It was built for one person first** — someone who is not technical, whose phone has to work in a
   car and a kitchen, and who will never open a terminal. Every rough edge that survived testing is an
   edge she would have hit.

## The invariants

Break one of these and the product is wrong, however well the code compiles.

1. **A sync never loses data.** State resolves by recency with the loser kept. Conversations are
   unioned by id, never merged. There is no delete verb. If you add one, add tombstones at the same
   time or you will delete someone's history.
2. **Credentials never travel.** The whitelist in `sync_routes.py` is the whole surface. Adding
   `providers.json` or `credentials.key` to it is one line and would leak every key on both machines.
3. **No model in the data path.** The message relay exists; do not route files through it. A model
   turn is allowed to rewrite what it forwards, and a rewritten memory file is silent loss.
4. **A failure is a sentence, not a hang.** Anything that reaches the network has a short timeout and
   returns text a person can read. The 3-second connect timeout is load-bearing: it is what makes "is
   the computer on?" an answerable question.
5. **The phone pays for every pixel.** Landscape is ~800×360 CSS px. Space comes out of text and
   chrome, never out of a touch target (~44 px). Never say the same thing twice on one screen.
6. **The persona is a build parameter.** `PERSONA_SRC=… ./build-apk.sh` — one codebase, many
   assistants, no forks.

| `tools/` | capture, annotate, build the guide, scan for identifying material |
| `docs/screenshots/` | product shots, cropped to the app surface |

The application source itself is a separate project; this repository documents, wraps and syncs it.

## How the pieces talk

```
phone app ──HTTP──> desktop room daemon
                    ├── /api/state      (which boxes are alive)
                    ├── /api/send       (message relay between agent instances)
                    └── /api/sync/*     (this project: deterministic file sync)
```

If you change the sync, the client that must keep working is in the app (`app/src-tauri/src/sync.rs`
in the application repository): it walks a list of configured computers, compares a manifest of
hashes, and writes conflict copies on disagreement. Both ends implement the same rules; a change on
one side alone produces a sync that appears to work and quietly does nothing.

## Verifying, without trust

```bash
# the package must not carry identifying material
/usr/bin/python3 tools/doxcheck.py .

# the guide must rebuild to the same page numbers, with no drift
/usr/bin/python3 tools/build_guide.py

# a round trip against a live daemon
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8790/api/sync/manifest
curl -s -X PUT --data-binary @file 'http://127.0.0.1:8790/api/sync/file?path=memory/MEMORY.md'
curl -s 'http://127.0.0.1:8790/api/sync/file?path=memory/MEMORY.md' | sha256sum
```

A sync is correct when a second pass moves nothing. Run it twice; the second pass is the assertion.

## Known gaps, stated plainly

| Gap | Consequence | Where it goes |
|---|---|---|
| No background trigger yet | a phone that is never opened never syncs; the hourly worker needs the client moved into the shared native library first | `docs/SYNC.md`, "When it runs" |
| No sync settings UI | a release build cannot be pointed at a desktop without writing a file; debug builds can, via adb | app Settings → Sync |
| Conversation history import | memory imports, past transcripts do not | one-time importer |
| In-app mail send | fills every field, stops one tap short: the provider only sends on trusted input | the user's own tap, or an accessibility service — a bigger decision |
| Android Auto | the menu path is documented, not photographed on a device that has it | a device with Android Auto |

## Tone

The documentation is written for a person who is not impressed by jargon and does not have time. Short
sentences, real numbers, and a stated cost for every claim. Where something is unfinished it says so in
the same voice as everything else — a document that only lists successes is not a document anyone can
work from.
